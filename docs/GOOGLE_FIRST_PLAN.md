# VPyLab 구글 중심 전환 계획

작성: 2026-11-07. 고침: 2026-11-12(세 단계 방향 확정, 2단계 구현). 상태: 2단계 구현, 실제 수업 확인 전.

## 0. 세 단계 (2026-11-12 확정)

VPyLab은 로그인 없이 시작하고, 필요한 만큼만 계정을 연결합니다. 두 판 모두 같은 흐름을 따릅니다.

| 단계 | 필요한 것 | 할 수 있는 일 | 데이터가 있는 곳 |
|---|---|---|---|
| 1. 혼자 만들기 | 없음 | 실행, 학습 자료, 공유 링크, HTML·파이썬 파일 내려받기와 "파일 열기", 이 브라우저의 초안 | 학생의 브라우저와 파일. 공유 링크의 코드만 운영 저장소 |
| 2. 저장 | 구글 계정 | 만들기 화면의 "저장"으로 학생 본인의 구글 드라이브에 저장, 다른 기기에서 열기 | 학생의 구글 드라이브 |
| 3. 팀 프로젝트 | GitHub 계정(선택) | 팀 프로젝트를 열어 둔 동안 저장이 GitHub 커밋이 됨. 팀원 초대, 기록 | GitHub 저장소 |

같은 날 정한 것은 다음과 같습니다.

- 짧은 공유 링크는 만료 없이 보관합니다. 학생이 공유 링크를 저장 용도로 사용해도 됩니다. 그래서 아래 3단계의 "공유는 코드를 담은 URL만"은 적용하지 않습니다.
- 팀 협업은 구글 드라이브가 아니라 GitHub가 맡습니다. `drive.file` 권한으로는 앱이 만든 파일만 열 수 있어 팀원이 공유한 파일을 열 수 없기 때문입니다. 그래서 아래 3단계의 "팀 프로젝트는 교실 서버로"는 GitHub로 바꿉니다.
- 교사가 학생의 드라이브 저장 코드를 직접 볼 수 없는 것은 받아들입니다. 제출은 공유 링크나 파일로 합니다.
- GitHub는 13세 이상 계정이 필요하므로 선택 기능으로 둡니다.

구현 위치는 다음과 같습니다.

- 저장 방식 분기: `client/src/pages/Sandbox.jsx`의 `DRIVE_EDITOR`·`TEAM_PROJECTS`·`ACCOUNT_SAVE`, 배포 설정값은 `client/src/lib/api-base.js`의 `DRIVE_SAVE`·`GITHUB_ADDON`·`TEAM_PROJECTS`
- 파일 열기와 내려받기: `client/src/utils/code-file.js`. 내려받은 HTML에는 코드가 Base64로 들어 있어 다시 열 수 있습니다.
- 로그인 없는 초안: `client/src/utils/sandbox-draft.js`(이 브라우저, 14일). 학습 자료의 연습 초안은 공용 컴퓨터를 고려해 탭 단위로 둡니다.
- 드라이브 연결 유지: 토큰과 연 파일 ID를 탭 저장소에 두고(`client/src/drive-lab/google-auth.js`, `client/src/drive/driveSession.js`의 `resume`), 만료 뒤 저장하면 그 클릭 안에서 다시 승인받습니다(`renewInGesture`).
- 오픈소스 판의 GitHub 팀 프로젝트: `client/src/github/`, 토큰 교환 함수 `functions/api/github/token.js`. 수업용 판은 기존 운영 서버 방식을 유지합니다.

## 1. 목표와 원칙

VPyLab을 전 세계 학교가 사용하는 오픈소스 서비스로 키우려면 개인정보 부담과 운영 비용이 학생 수에 비례해 늘지 않아야 합니다. 그래서 다음 원칙을 따릅니다.

1. **운영자는 학생 데이터를 보관하지 않습니다.** 학생 코드는 학생 본인의 구글 드라이브에, 수업 협업 기록은 학교(교사) 컴퓨터의 교실 서버에 둡니다.
2. **상시 서버와 DB를 두지 않습니다.** 운영자가 부담하는 것은 정적 호스팅뿐입니다.
3. **구글 로그인은 신원 확인과 드라이브 권한에만 사용합니다.** 권한 범위는 `drive.file`(앱이 만든 파일만)로 제한합니다.
4. **저장소는 어댑터로 분리합니다.** Microsoft 365를 사용하는 학교를 위해 OneDrive 어댑터를 붙일 수 있게 합니다.
5. **누구나 자체 배포할 수 있습니다.** 비밀값 없이 자기 OAuth 클라이언트 ID만 넣으면 됩니다.

## 4. 단계

각 단계는 통과 기준을 만족해야 다음으로 넘어갑니다.

### 0단계: 실험 (진행 중)

- 내용: `/drive-lab.html` 실험 페이지([DRIVE_LAB.md](DRIVE_LAB.md))를 오픈소스 VPyLab의 운영 주소에 올리고 당곡고 학생 계정으로 시험합니다. 운영 주소를 마련하려면 Vercel에서 `vpylab/vpylab` 저장소로 새 프로젝트를 만듭니다.
- 통과 기준:
  - 학생 계정 승인이 되거나, 관리 콘솔에서 무엇을 바꾸면 되는지 확인됨(A1)
  - 저장·다른 기기·충돌·만료 복구에서 데이터 유실 0건(B·C)
  - 구글 외 출처 0곳(D1)
  - 학생 30명 동시 연속 저장에서 오류율과 지연이 수업에 지장 없는 수준(E1)

### 1단계: OAuth 운영 준비

- 구글 클라우드 프로젝트의 소유 계정을 정합니다. 글로벌 오픈소스라면 특정 학교 도메인이 아닌 별도 계정(또는 조직)이 맞습니다. "내부" 대상은 한 도메인 안에서만 사용할 수 있기 때문입니다.
- 동의 화면을 **외부·운영**으로 바꿉니다. 권한이 비민감 범위뿐이므로 보안 평가는 필요 없을 것으로 봅니다(미확인). 다만 앱 이름·로고를 보이려면 브랜드 인증이 필요하고, 이를 위해 홈페이지, 개인정보처리방침, 소유를 확인한 도메인이 필요합니다.
- `vercel.app` 하위 주소로 도메인 소유 확인이 되는지는 확인하지 않았습니다. 자체 도메인(예: vpylab.org)을 준비하는 편이 안전합니다.
- 개인정보처리방침에 데이터 위치(학생 드라이브, 교실 서버), 운영자가 받는 것(정적 호스팅의 접속 기록뿐), 삭제 방법(드라이브 폴더 삭제, 권한 철회)을 적습니다.

### 2단계: 본 앱 저장 전환

- `drive-storage.js`를 본 앱의 저장 계층으로 옮기고, `codeStore`가 어댑터 인터페이스(`list`·`create`·`open`·`save`·`revisions`·`trash`)만 보도록 바꿉니다.
- 저장 모드는 둘입니다. 로그인하지 않으면 브라우저(localStorage)에, 구글로 로그인하면 드라이브에 저장합니다.
- 실험 페이지에서 검증한 초안 보존, 충돌 처리, 덮어쓰기 감지, 계정 전환 처리, 로그아웃 정리를 그대로 가져옵니다.
- 본 앱의 CSP를 바꿉니다. 지금은 실험 페이지에만 전용 CSP가 있습니다. 본 앱 CSP의 `connect-src`에 `https://www.googleapis.com`, `https://oauth2.googleapis.com`을 넣고 `script-src`·`frame-src`에 구글 로그인(`https://accounts.google.com/gsi/`)을 넣습니다. Supabase와 Railway 주소는 4단계에서 뺍니다.
- 기능 플래그(`VITE_STORAGE=drive`)로 켜고, 교실에서 한 학기 병행합니다.

### 3단계: 기능 정리

- 공유는 코드를 담은 URL만 남깁니다. 길이 한도를 넘으면 드라이브 파일 공유 안내로 대신합니다.
- 갤러리는 GitHub Pages 발행 결과를 모은 정적 목록으로 바꿉니다. 목록 갱신은 GitHub Actions가 맡습니다.
- 팀 프로젝트, 동료 리뷰, 교사 대시보드는 교실 서버로 옮깁니다.

### 4단계: 데이터 이전과 종료

- 기존 사용자에게 내보내기(내려받기 또는 드라이브로 옮기기) 기간을 알립니다.
- 기간이 지나면 Supabase의 VPyLab 테이블을 삭제하고 Railway 서버를 종료합니다. 삭제는 되돌릴 수 없으므로 백업과 공지를 확인한 뒤 진행합니다.

### 5단계: 오픈소스 공개

- 자체 배포 안내: 클라이언트 ID 만들기, 승인된 원본, `VITE_GOOGLE_CLIENT_ID`
- 학교 관리자 안내: 관리 콘솔에서 앱 허용(Limited·Trusted), 학부모 동의는 학교 책임이라는 점
- 여러 언어 안내서(한국어·영어부터)

## 5. 개인정보 정리

| 데이터 | 위치 | 운영자 접근 |
|---|---|---|
| 학생 코드·버전 | 학생 구글 드라이브 `VPyLab` 폴더 | 없음 |
| 저장 전 초안, 실험 기록 | 학생 브라우저 localStorage(계정별) | 없음 |
| 구글 액세스 토큰 | 브라우저 탭 저장소(새로 고침에는 유지, 탭을 닫으면 사라짐) | 없음 |
| 로그인 없이 작성하던 코드 | 학생 브라우저 localStorage(14일) | 없음 |
| GitHub 액세스 토큰(오픈소스 판) | 브라우저 탭 저장소. 발급할 때 Pages 함수를 거치지만 함수는 저장하지 않음 | 없음 |
| 수업 협업 기록 | 교사 컴퓨터의 교실 서버(SQLite) | 없음 |
| 접속 기록(IP 등) | 정적 호스팅(Vercel) | 호스팅 사업자 정책을 따름 |

- 미성년자 앱 사용의 학부모 동의는 구글 정책상 학교(기관)에 책임이 있습니다.
- 공용 컴퓨터에서는 로그아웃 때 초안을 지우고, 구글 계정에서도 로그아웃하도록 안내합니다.

## 6. 비용

- 운영자: 정적 호스팅 비용만 남습니다. Railway 비용이 없어집니다. Supabase 요금은 pythink2가 같은 프로젝트를 사용하므로 그대로입니다.
- 구글 Drive API: 표준 사용은 무료입니다. 프로젝트 일일 4억 unit을 넘는 사용에 2026년 하반기부터 과금이 예정되어 있습니다. 저장 1회는 확인(읽기 5), 쓰기(편집 50), 덮어쓰기 확인(목록으로 계산하면 100)으로 최대 약 155 unit입니다. 하루 약 250만 회 저장까지 무료 범위로 추산합니다. 버전 기록 조회가 실제로 몇 unit인지는 확인하지 않았습니다.

## 8. 결정이 필요한 것

1. 구글 클라우드 프로젝트를 어느 계정(조직)이 소유할지
2. 자체 도메인(vpylab.org 등)을 마련할지
3. 갤러리의 좋아요·조회수를 포기해도 되는지
4. 2단계 병행 기간(한 학기)과 4단계 종료 시점
