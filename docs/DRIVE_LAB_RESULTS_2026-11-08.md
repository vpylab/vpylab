# 드라이브 저장 실험 안정성 시험 결과 (2026-11-08)

배포: https://vpylab.pages.dev/drive-lab (Cloudflare Pages, 오픈소스 판)
구글 OAuth: 개인 gmail의 GCP 프로젝트 `vpylab`, 동의 화면 "외부·테스트 중"(시험 뒤 같은 날 "프로덕션"으로 게시), 범위 `openid email profile drive.file`
시험 계정: 개인 gmail 1개, 당곡고 교사 계정(danggok.hs.kr) 1개
"기기 2"는 등록된 다른 출처(`http://localhost:4086`)에서 연 같은 앱입니다. 브라우저 저장소와 기기 표식이 따로라 다른 기기와 같은 조건입니다.

## 체크리스트

| 항목 | 결과 | 확인한 내용 |
|---|---|---|
| A1 학생 계정 | 미실시 | 학생 시험 계정이 없어 하지 못했습니다. 학교마다 관리자 정책이 다릅니다. |
| A2 교사 계정 | 통과 | danggok.hs.kr 교사 계정이 관리자 설정 없이 승인되고 파일 만들기·저장이 됐습니다. 테스트 사용자로 등록하지 않았을 때는 `403 access_denied`가 나왔습니다. |
| A3 드라이브 권한만 빼고 승인 | 통과 | 구글 동의 화면의 드라이브 체크 상자는 **처음에 비어 있습니다.** 그대로 계속을 누르면 페이지가 "드라이브 권한 다시 요청"을 안내하고, 다시 요청하면 드라이브 권한만 추가로 묻습니다. |
| B1 저장·다시 열기 | 통과 | 새로 고침 뒤 다시 로그인해도 내용이 같고, 내 드라이브에 VPyLab 폴더가 생깁니다. 특수 문자·CRLF·탭·이모지·제로폭 문자·빈 파일·99KB 파일이 한 글자도 바뀌지 않았습니다. 100KB 초과(바이트 기준)는 보내지 않고 알립니다. |
| B2 다른 기기에서 열기 | 통과 | 기기 2에서 같은 내용이 열렸습니다. |
| B3 충돌 감지 | 통과 | 같은 브라우저 두 탭, 서로 다른 두 기기 모두 충돌 화면이 나왔고 세 선택지(사본 저장, 드라이브 내용 사용, 덮어쓰기)가 모두 동작했습니다. |
| B4 버전 기록 | 통과 | 이전 버전을 편집기로 불러오고 "저장해야 반영" 안내가 나옵니다. |
| C1 만료 흉내 | 통과 | 초안이 남고, 다시 승인 한 번으로 계정 선택 없이 저장이 이어집니다. |
| C2 실제 1시간 만료 | 통과 | 18:16에 승인한 탭에서 19:16 이후 저장하니 초안이 남고, 다시 승인 뒤 저장됐습니다. |
| C3 권한 철회 | 통과 | 앱 안 철회는 로그아웃과 함께 처리됩니다. 앱 밖에서 철회한 경우(토큰 무효화)에도 저장이 초안을 남기고 재승인을 안내하며, 재승인 뒤 기존 파일이 그대로 보입니다. |
| D1 연결된 출처 | 통과 | 구글 주소와 페이지 자신뿐입니다. 번들에 Supabase·Railway 주소가 없습니다. |
| D2 접근 범위 | 통과 | 앱 토큰으로 드라이브 전체를 조회해도 앱이 만든 11개만 보이고, 사용자가 직접 만든 문서를 ID로 열면 404입니다. |
| E1 연속 저장 | 통과 | 30회 연속 평균 3.0초, 오류 0회. 두 탭에서 동시에(30회 + 15회) 저장해도 오류 0회였습니다. |

## 장애 주입 시험(페이지의 fetch를 가로채 실패를 흉내 냄)

| 상황 | 결과 |
|---|---|
| 모든 요청 네트워크 끊김 | 초안이 남고 "네트워크 연결에 실패" 안내, 복구 뒤 저장 성공 |
| 쓰기 요청만 1회 끊김 | 자동으로 다시 보내 저장(아래 결함 2 수정 뒤 4/4) |
| 503 두 번(쓰기/조회) | 백오프 뒤 저장 |
| 429 + Retry-After | 기다린 뒤 저장 |
| 403 userRateLimitExceeded | 다시 시도해 저장 |
| 응답 유실(쓰기는 반영됨) | 해시로 반영을 확인해 두 번 쓰지 않음 |
| 500 계속 | 세 번 시도 뒤 "잠시 뒤 다시 시도" 안내 |
| 403 storageQuotaExceeded | "저장 공간이 가득 참" 안내 |
| 404 | "파일을 찾을 수 없음" 안내 |
| 20초 무응답 | 시간 초과 뒤 버전을 확인하고 저장 |
| 401 | 초안 유지, "다시 승인" 뒤 이어서 저장 |

## 찾아서 고친 결함

| # | 결함 | 영향 | 고친 방법 |
|---|---|---|---|
| 1 | 같은 이름으로 새 파일을 만들면 이름이 같은 파일이 둘 생김 | 목록에서 구분 불가 | "이름 (2).py"처럼 번호를 붙임(사본·되살린 버전 포함) |
| 2 | 드라이브는 저장 2~4초 뒤 내용 변경 없이 `version`만 올림. 쓰기가 실패해 다시 보내는 경로가 이를 다른 기기 저장으로 오인 | 학교망에서 연달아 저장할 때 거짓 충돌 화면(실측 2회 중 1회) | 다시 보낼지 판단을 `headRevisionId`(내용 버전) 기준으로 바꿈 |
| 3 | 같은 브라우저 다른 탭이 저장해도 "다른 기기가 먼저 저장" | 학생 혼란 | "이 브라우저의 다른 탭(창)에서"로 구분 |
| 4 | 덮어쓰기 확인을 `version`으로 비교 | 충돌 화면을 보는 사이 버전 숫자만 오르면 다시 충돌 | 내용 버전으로 비교 |
| 5 | 다른 탭에서 휴지통으로 옮긴 파일에 저장해도 "저장했습니다" | **30일 뒤 삭제되는 파일에 저장**(자료 손실) | 휴지통 파일은 저장·열기를 막고 초안을 남기며 안내 |
| 6 | 드라이브에서 이름을 바꾼 뒤 저장해도 편집기 제목이 옛 이름 | 혼란 | 저장 응답의 이름으로 맞춤 |
| 7 | 드라이브 권한 빠짐 안내가 체크 상자를 직접 체크해야 한다고 말하지 않음 | 승인 반복 | 안내 문구 보완 |
| 8 | VPyLab 폴더를 휴지통으로 옮기면 목록이 비고, 열린 탭에서는 새 파일을 휴지통 폴더 안에 만듦. 새로 열면 빈 새 폴더를 몰래 만듦 | **자료 손실**·파일이 사라진 것처럼 보임 | 멈추고 "VPyLab 폴더 되살리기" 버튼 제공 |
| 9 | 같은 탭에서 다른 계정으로 바뀌어도 앞 계정의 폴더 ID를 계속 사용 | 공용 PC에서 다음 학생의 목록이 비고 새 파일 만들기 실패 | 계정 전환·로그아웃 때 폴더 기억을 지우고, 폴더를 찾을 수 없으면 다시 찾음 |
| 10 | 편집기 내용·열린 파일을 담는 ref를 화면 그린 뒤(useEffect) 맞춤 | 느린 기기에서 파일을 연 직후 클릭이 지난 값을 읽어 엉뚱한 초안을 남김(테스트에서 간헐 실패로 드러남) | `useLayoutEffect`로 바꿔 즉시 맞춤 |
| 11 | 오픈소스 판 **도구 → 공유**가 `/api/share` 405로 실패 | 공유 불가 | 서버 없는 판은 코드를 링크 주소(`#code=`)에 담음, 임베드 버튼 숨김 |

테스트: 단위·화면 테스트 1072개 통과(드라이브 실험 138개, 공유 3개 추가). 테스트용 가짜 드라이브가 부모 폴더와 휴지통을 무시해 결함 9를 가렸으므로 실제 드라이브처럼 고쳤습니다.
