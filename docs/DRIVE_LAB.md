# 구글 드라이브 저장 실험

오픈소스 VPyLab(`vpylab/vpylab`)을 서버와 DB 없이 운영할 수 있는지 확인하는 실험입니다. 수업용 GitHub 연동 버전도 2026-11-09부터 같은 저장소에서 배포합니다(예전 저장소 `greatsong/vpylab-classroom`). 학생 코드는 학생 본인의 구글 드라이브 `VPyLab` 폴더에 저장하고, 브라우저는 구글 API와만 통신합니다. 전체 전환 계획은 [GOOGLE_FIRST_PLAN.md](GOOGLE_FIRST_PLAN.md)에 있습니다.

- 화면: `client/drive-lab.html` → `client/src/drive-lab/`
- 저장 어댑터: `client/src/drive-lab/drive-storage.js` (`list`·`create`·`open`·`save`·`revisions`·`revisionContent`·`trash`). 같은 메서드를 구현하면 OneDrive 등 다른 저장소로 바꿀 수 있습니다.
- 인증: `client/src/drive-lab/google-auth.js` (Google Identity Services 토큰 방식, 토큰은 메모리에만 둡니다)
- 권한: `openid email profile` + `drive.file`. `drive.file`은 구글 분류상 비민감 범위이며, 이 앱이 만든 파일만 다룹니다.

## 1. 구글 클라우드 준비 (한 번)

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 프로젝트를 만듭니다.
2. **API 및 서비스 → 라이브러리**에서 **Google Drive API**를 사용 설정합니다.
3. **Google 인증 플랫폼(OAuth 동의 화면)**을 설정합니다.
   - 학교 계정으로 만든 프로젝트에서 대상을 **내부**로 두면 같은 도메인 계정만 사용할 수 있고 테스트 사용자 등록이 필요 없습니다. 학교 안 실험에 알맞습니다.
   - 다른 학교나 개인 계정도 시험하려면 **외부 + 테스트 중**으로 두고 시험할 계정을 테스트 사용자로 등록합니다(최대 100명).
   - 데이터 액세스에 `.../auth/drive.file`을 추가합니다.
4. **클라이언트 → 클라이언트 만들기 → 웹 애플리케이션**을 선택하고, **승인된 JavaScript 원본**에 아래 주소를 모두 등록합니다.
   - `http://localhost:4086` (로컬 개발·미리보기)
   - 오픈소스 VPyLab의 운영 주소(예: 자체 도메인 `https://vpylab.org`). `https://vpylab.vercel.app`은 수업용 배포 주소입니다.
   - 승인된 원본은 와일드카드를 받지 않습니다. Vercel 미리보기 배포 주소(`vpylab-xxxx.vercel.app`)는 배포마다 바뀌므로 등록할 수 없습니다. 실제 계정 시험은 로컬이나 운영 주소에서 합니다.
   - 리디렉션 URI는 비워 둡니다. 팝업 토큰 방식이라 사용하지 않습니다.
5. 만들어진 **클라이언트 ID**(`숫자-문자.apps.googleusercontent.com`)를 복사합니다. 클라이언트 ID는 공개값입니다. 클라이언트 보안 비밀번호는 사용하지 않으며 저장소에 넣지 않습니다.

## 2. 학생 계정 허용 (학교 관리자)

18세 미만으로 지정된 학생 계정은 관리자가 설정하지 않은 앱을 사용할 수 없습니다. 체크리스트 A1을 먼저 기록한 뒤 아래 설정을 바꿔 다시 시험하면, 학교에 요청할 내용을 정확히 알 수 있습니다.

- 관리 콘솔 → 보안 → 액세스 및 데이터 제어 → API 제어 → 앱 액세스 제어에서 위 클라이언트 ID로 앱을 추가하고 **제한됨(Limited)** 또는 **신뢰함(Trusted)**으로 지정합니다.
- 학교가 드라이브를 제한된 서비스로 지정했다면 **신뢰함**이어야 합니다.
- 메뉴 이름은 관리 콘솔 버전에 따라 다를 수 있습니다.
- 관리자가 막으면 화면에 "학교 관리자가 이 앱을 아직 허용하지 않았습니다"가 표시됩니다.

## 3. 실행

### 로컬 개발

```bash
cd client
npm run dev:drive-lab
```

`http://localhost:4086/drive-lab.html`을 엽니다. 개발 모드에서는 클라이언트 ID를 화면에 입력할 수 있고, 입력한 ID는 이 브라우저에만 저장됩니다.

### 운영 배포

1. `client/.env.production`에 `VITE_GOOGLE_CLIENT_ID=<클라이언트 ID>`를 추가합니다(공개값이라 커밋해도 됩니다). Vercel 프로젝트 환경변수로 넣어도 됩니다.
2. Vercel은 `vercel.json`의 `npm run build:deploy`로 본 앱을 빌드한 뒤 실험 페이지를 같은 `client/dist`에 덧붙입니다.
3. 배포 후 `<운영 주소>/drive-lab.html`을 엽니다. `/drive-lab`으로 열어도 `/drive-lab.html`로 넘어갑니다.
4. 학교 밖 계정까지 쓰려면 OAuth 동의 화면을 "운영"으로 게시해야 합니다. 브랜드 확인에 필요한 것은 [GOOGLE_FIRST_PLAN.md](GOOGLE_FIRST_PLAN.md)의 1단계에 정리했습니다.

운영 빌드에서는 클라이언트 ID 입력칸이 표시되지 않습니다. 화면에서 임의의 ID를 넣게 하면 남의 앱에 학생 계정 권한을 주도록 유도하는 링크를 만들 수 있기 때문입니다. 자체 배포할 때는 자기 클라이언트 ID를 `VITE_GOOGLE_CLIENT_ID`로 넣습니다.

배포 전에 운영과 같은 헤더로 확인하려면 다음을 실행합니다.

```bash
cd client
VITE_GOOGLE_CLIENT_ID=<클라이언트 ID> npm run build:deploy
npm run preview:deploy
```

미리보기 서버는 `vercel.json`의 `/drive-lab.html` 헤더(CSP 포함)를 그대로 겁니다. 미리보기 서버는 모든 경로에 이 헤더를 걸기 때문에 본 앱(`/`)에서 글꼴 CSP 오류가 보일 수 있습니다. 운영에서는 경로별로 헤더가 나뉘므로 생기지 않습니다.

### 배포 설정이 하는 일

| 설정 | 내용 |
|---|---|
| `vercel.json` rewrite·redirect | `/drive-lab.html`은 SPA의 `index.html`로 보내지 않고, `/drive-lab`은 `/drive-lab.html`로 넘깁니다. |
| `vercel.json` 헤더 | `/drive-lab.html`에만 전용 CSP를 겁니다. 구글 로그인(`accounts.google.com/gsi/`), 드라이브 API(`www.googleapis.com`), 권한 철회(`oauth2.googleapis.com`, 구글 로그인 라이브러리가 사용), 내려받기 리디렉션 대비(`*.googleusercontent.com`)만 더 허용하고, Supabase와 운영 서버는 허용하지 않습니다. 승인 팝업을 위해 `Cross-Origin-Opener-Policy: same-origin-allow-popups`를 둡니다. |
| 서비스 워커 | 앱 셸이 아닌 HTML 페이지 이동은 가로채지 않습니다. 실험 페이지가 본 앱의 오프라인 앱 셸을 덮어쓰지 않습니다. 실험 페이지는 오프라인에서 열리지 않습니다. |
| 사전 캐시 | 실험 페이지 파일은 본 앱 서비스 워커의 사전 캐시에 들어가지 않습니다. |

이 내용은 `client/scripts/drive-lab-deploy.test.mjs`가 검사합니다.

## 4. 시험 방법

화면의 **6. 실험 체크리스트**를 위에서부터 진행하고 결과와 관찰 내용을 적습니다.

| 묶음 | 확인하는 것 |
|---|---|
| A 계정 | 학생·교사 계정 승인, 드라이브 권한만 거부했을 때의 안내 |
| B 저장 | 저장·다시 열기, 다른 기기, 두 기기 충돌, 버전 기록 |
| C 토큰 | 만료 흉내, 실제 1시간 뒤 저장, 권한 철회 |
| D 개인정보 | 구글 외 출처가 없는지, 앱이 만들지 않은 파일이 보이지 않는지 |
| E 부하 | 연속 저장 시간과 오류 |

- **다른 기기(B2·B3):** 로컬에서는 다른 크롬 프로필이나 다른 브라우저로 두 기기를 대신합니다. 실제 다른 기기 시험은 운영 주소에서 합니다.
- **충돌 판정:** 저장하기 전에 드라이브의 버전을 확인합니다. 버전이 다르면 드라이브의 내용을 직접 받아 비교합니다.
  - 드라이브 내용이 내 코드와 같으면 저장하지 않습니다.
  - 드라이브 내용이 내가 연 때와 같으면(이름 변경처럼 내용은 그대로이고 버전만 오른 경우) 그대로 저장합니다.
  - 그 밖에는 충돌 화면을 보여 줍니다. 충돌 화면이 열려 있는 동안 "저장"은 막혀 있습니다.
- **오래된 초안:** 초안에는 시작한 버전이 함께 기록됩니다. 그 뒤 다른 곳에서 저장했다면 "초안 불러오기"를 누르는 즉시 충돌 화면으로 넘어갑니다.
- **덮어쓰기 버튼:** "내 코드로 덮어쓰기"는 충돌 화면에서 본 드라이브 버전일 때만 저장합니다. 화면을 보는 사이 또 다른 저장이 있으면 덮어쓰지 않고 새 충돌을 보여 줍니다.
- **쓰기 재시도:** 저장 요청은 자동으로 다시 보내지 않습니다. 서버 오류나 시간 초과가 나면 먼저 드라이브를 확인합니다. 내 내용이 이미 반영됐으면 그대로 끝내고, 그사이 다른 기기가 저장했으면 충돌로 보여 줍니다. 둘 다 아닐 때만 최대 2번 다시 보냅니다.
- **결과를 모르는 지난 저장:** 시간 초과로 끝난 저장 내용은 최근 3개까지 기억합니다. 다음 저장 때 드라이브 내용이 그중 하나면 내 저장이 반영된 것으로 보고 충돌로 다루지 않습니다.
- **덮어쓰기 감지:** 드라이브 API v3에는 조건부 쓰기가 없어서 확인과 쓰기 사이에 짧은 틈이 남습니다. 그래서 저장한 뒤 버전 기록을 다시 확인하고, 그 틈에 다른 기기의 저장을 덮어썼으면 알려 줍니다. 덮어쓴 내용은 "사본으로 되살리기"로 새 파일로 만들 수 있습니다.
- **버전 기록에 관해 확인하지 않은 것:** 구글이 오래된 버전을 언제 정리하는지, 짧은 간격의 저장을 한 버전으로 합치는지는 공식 문서로 확인하지 않았습니다. 합쳐진다면 덮어쓰기 감지가 일부를 놓칠 수 있습니다(놓치는 쪽이라 잘못 경고하지는 않습니다). 버전 기록을 백업 수단으로 믿지 않습니다.
- **파일 만들기 재시도:** 만들기 요청은 자동으로 다시 보내지 않습니다. 서버 오류나 시간 초과 뒤에는 만들기 표식으로 이미 만들어졌는지 확인하고, 없을 때만 다시 보냅니다. 같은 파일이 두 개 생기지 않게 하기 위해서입니다.
- **여러 학생 동시 저장(E1):** 학생 여러 명이 각자 계정으로 같은 시간에 연속 저장을 실행하면 학교 공유 IP 상황을 흉내 낼 수 있습니다. 저장 1회는 버전 확인, 쓰기, 덮어쓰기 확인의 세 요청입니다.

## 5. 공용 컴퓨터(컴퓨터실)

- 첫 로그인은 항상 구글 계정 선택 창을 띄웁니다. 로그인한 계정은 화면 오른쪽 위에 크게 표시합니다.
- 다시 승인할 때는 같은 계정을 지정해 요청합니다. 다른 계정이 승인되면 앞 계정의 화면을 비웁니다.
- "다시 승인"은 권한 만료로 실패한 바로 그 작업(저장 또는 새 파일)만, 그 파일이 지금도 열려 있을 때 이어서 합니다. 다른 작업이 실패한 경우에는 승인만 하고 작업은 다시 누릅니다.
- 로그인하기 전에 쓴 코드가 있으면, 로그인한 계정의 초안으로 옮길지 묻습니다. 다른 사람이 쓴 코드라면 "취소"를 눌러 지웁니다.
- 저장하지 못한 초안은 계정별로 이 브라우저(localStorage)에 남습니다. 초안은 탭마다 따로 저장하므로, 같은 파일을 두 탭에서 열거나 안내 중인 초안이 있는 상태에서 입력해도 다른 초안을 덮어쓰지 않습니다.
- 편집기의 "이 브라우저에 남은 다른 초안" 목록에서 초안을 살펴보거나 버릴 수 있습니다.
- 같은 파일을 두 탭에서 동시에 편집하지 않습니다. 한 탭에서 다른 탭의 초안을 버리거나, 그 파일을 휴지통으로 옮기거나, 로그아웃하며 초안을 지우면 다른 탭의 초안도 지워집니다. 그 탭에서 다시 입력하면 초안이 새로 저장됩니다.
- 구글 응답을 기다리는 동안(열기, 저장, 휴지통, 이전 버전, 승인 창)에는 편집기가 잠깁니다. 기다리는 사이 입력한 내용이 덮이지 않게 하기 위해서입니다.
- 같은 파일을 다시 열면, 이 탭에서 저장하지 못한 편집 내용은 다른 탭 초안의 시각과 관계없이 별도 초안으로 남습니다.
- 초안이나 이전 버전을 불러올 때 편집 중이던 내용은 별도 초안으로 남깁니다. 다른 파일을 열거나 새 코드로 바꿀 때는 편집 중이던 파일의 초안이 그대로 남습니다.
- 브라우저 저장 공간이 가득 차 초안을 저장하지 못하면 빨간 경고를 띄웁니다. 이 상태에서는 다른 파일을 열거나 새 코드로 바꿀 때 "내용을 잃습니다"라고 다시 묻고, 다른 계정이 승인되면 화면을 비우기 전에 코드를 `.py` 파일로 내려받을지 묻습니다. 초안이나 이전 버전을 불러오는 동작은 내용을 남길 수 없으면 멈춥니다.
- **로그아웃**을 누르면 그 계정의 초안을 지울지 묻습니다. 공용 컴퓨터에서는 지웁니다. 로그아웃하지 않고 창만 닫으면 초안이 남습니다. 14일이 지난 초안은 그 컴퓨터에서 이 페이지를 다시 열 때 지워지므로, 다시 열지 않으면 계속 남습니다.
- 로그인하기 전에 쓴 코드는 탭 저장소(sessionStorage)에만 남고 탭을 닫으면 사라집니다. 그런 코드가 있으면 창을 닫을 때 경고합니다. 로그인하면 그 계정의 초안으로 옮겨집니다. 브라우저 저장 공간이 가득 차 옮기지 못한 초안은 로그인한 동안 목록에 보이지 않으니, 로그아웃해 확인하거나 공간을 비운 뒤 다시 로그인합니다.
- 초안을 버릴 때는 확인 창을 띄웁니다. 버린 초안은 되돌릴 수 없습니다.
- 저장하지 못한 초안은 14일이 지나면 지워집니다. 방학처럼 오래 쉬기 전에는 드라이브에 저장해 둡니다.
- 이 페이지의 로그아웃은 브라우저의 구글 로그인 상태를 바꾸지 않습니다. 그래서 로그아웃하면 "구글 계정에서도 로그아웃" 링크를 보여 줍니다. 구글 계정에서 로그아웃하지 않으면 다음 사람이 계정 선택 창에서 앞 사람 계정을 고를 수 있습니다. 수업이 끝나면 학생이 이 링크로 로그아웃하도록 안내합니다.

## 6. 결과 전달

**7. 보고서**의 **보고서 복사**를 누르고 Claude에게 붙여 넣습니다. 보고서에는 이메일 대신 계정 도메인만 들어갑니다. 체크리스트와 결과는 이 브라우저의 localStorage에만 남습니다.

## 7. 정리

- 실험 파일은 drive.google.com의 `VPyLab` 폴더에 있습니다. 폴더를 옮기거나 이름을 바꿔도 앱이 같은 폴더를 찾습니다. 화면의 **휴지통** 버튼은 휴지통으로만 옮깁니다.
- 목록은 최근에 고친 파일부터 1,000개까지 보여 줍니다. 넘으면 화면에 알립니다.
- 앱 권한을 완전히 지우려면 화면의 **권한 철회**를 누르거나 [Google 계정 → 보안 → 타사 앱](https://myaccount.google.com/connections)에서 삭제합니다.
